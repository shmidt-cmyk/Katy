# Помощник по поиску вакансий

Личный помощник ищет вакансии через официальный HH API, присылает их в Telegram, а ты вручную оцениваешь каждую. Только после «Нравится» приложение получает полное описание вакансии через API и Gemini готовит черновик сопроводительного письма по твоему резюме/профилю. Используется авторизация приложения; бот не получает доступ к аккаунту соискателя, не откликается на вакансии и не входит в аккаунт hh.ru.

Клиент получает app access token через OAuth `client_credentials` из `HH_CLIENT_ID` и `HH_CLIENT_SECRET`, использует его только в памяти и не сохраняет в базе. Запросы идут на официальный API с настраиваемым `HH_USER_AGENT`; при HTTP 403/429 сбор останавливается без повторов и обходов ограничений. Если API недоступен, используй ручное добавление вакансии (`add`).

## Настройка

Скопируй `.env.example` в `.env`, заполни параметры MySQL, `HH_CLIENT_ID`, `HH_CLIENT_SECRET`, уникальный `HH_USER_AGENT` с контактным email, ключи Gemini и Telegram, chat ID и достоверный профиль кандидата. Не присылай секреты в чат и не добавляй `.env` в Git. Можно указать UTF-8 текстовое резюме локальным путём в `CANDIDATE_RESUME_FILE`; при этом содержимое резюме и вакансии передаётся Gemini для генерации, поэтому убери из файла контакты и другие лишние персональные данные. Локальный `resume.txt` уже добавлен в `.gitignore`.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m job_pipeline init-db
```

Проект создаёт и использует только таблицы с префиксом `jobpipe_`; существующая схема не меняется.

## Цикл работы

Запусти бота в отдельном терминале:

   ```sh
   python -m job_pipeline bot
   ```

После запуска бот сразу выполнит сбор, затем будет проверять новые вакансии с интервалом `HH_SCAN_INTERVAL_MINUTES` (по умолчанию раз в 6 часов). Новые карточки автоматически придут в Telegram.

При необходимости сбор и отправку карточек можно запустить вручную:

   ```sh
   python -m job_pipeline fetch
   python -m job_pipeline review
   ```

Нажми «Нравится» или «Не нравится». При положительной оценке приложение запросит полное описание вакансии через HH API и попросит Gemini сгенерировать черновик. Проверь письмо перед любым использованием.

`fetch` и `review` можно запускать снова: уже сохранённые вакансии не дублируются, повторно отправляются только вакансии со статусом `new`.

## Поисковые настройки

- `HH_SEARCH_QUERY` — текст запроса.
- `HH_CLIENT_ID` и `HH_CLIENT_SECRET` — реквизиты зарегистрированного приложения HH; не публикуй их.
- `HH_USER_AGENT` — уникальное имя приложения и контактный email для запросов API.
- `HH_AREA` — код региона.
- `HH_PER_PAGE` — число результатов на странице, от 1 до 100.
- `HH_MAX_PAGES` — максимум страниц за один запуск.
- `HH_REQUEST_DELAY` — минимальная пауза между страницами и запросами описаний в секундах (не менее 1).
- `HH_SCAN_INTERVAL_MINUTES` — период автоматического сбора при запущенном боте (не менее 60 минут).

## Ручное добавление вакансии

Если автоматический сбор запрещён или недоступен, можно добавить вакансию вручную:

```sh
python -m job_pipeline add \
  --title "Системный аналитик" \
  --company "Название компании" \
  --city "Москва" \
  --url "https://hh.ru/vacancy/..." \
  --description-file ./vacancy-description.txt
```

## Проверка Telegram-бота на тестовой базе

Для проверки без запроса к hh.ru и без вызовов Gemini открой `sql/demo_database.sql` в MySQL Workbench и выполни весь скрипт. Он создаст отдельную базу `hh_automation_test`, таблицы `jobpipe_*` и несколько фиктивных вакансий. Рабочая база не изменяется. Повторный запуск скрипта не сбрасывает статусы ранее добавленных демо-вакансий.

Затем из каталога проекта запусти бота, временно переопределив базу и включив демо-режим:

```sh
DB_NAME=hh_automation_test BOT_DEMO_MODE=true python3 -m job_pipeline bot
```

Для подключения к Telegram используются `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` из `.env`. Бот отправит новые демо-карточки и продолжит принимать нажатия, не обращаясь к hh.ru. Кнопка «Не нравится» проверит смену статуса, а «Нравится» создаст локальный тестовый черновик без Gemini. Тестовые ссылки ведут на `example.invalid` и не являются реальными вакансиями.

Демо-режим требует имя базы, оканчивающееся на `_test`, и игнорирует `DATABASE_URL` в пользу `DB_NAME`, чтобы случайно не подключиться к рабочей базе. Если в `.env` используется `DATABASE_URL`, для этой команды всё равно укажи `DB_NAME=hh_automation_test`; имя пользователя и пароль берутся из обычных `DB_USER`/`DB_PASSWORD`.

Останови процесс через `Ctrl+C`. Для обычного режима запусти бота без `BOT_DEMO_MODE=true`; демо-режим не сохраняется в `.env`, если задан только в команде запуска.

## Границы генерации

Промпт просит Gemini использовать только факты из `CANDIDATE_POSITION`, `CANDIDATE_STACK` и `CANDIDATE_EXPERIENCE`, не придумывать опыт и навыки, а текст вакансии обрабатывает как данные, а не инструкции. Генерация всё равно может ошибаться: проверяй письмо вручную.
